# 1. SQL Exercises

Use the following table for the exercises:

```text
events

event_id          STRING
user_id           STRING
event_type        STRING
event_timestamp   TIMESTAMP
domain            STRING
country           STRING
```

Example data:

```text
event_id | user_id | event_type | event_timestamp     | domain      | country
---------|---------|------------|---------------------|-------------|--------
e1       | u1      | search     | 2026-08-01 10:03:00 | expedia.com | ES
e2       | u1      | click      | 2026-08-01 10:04:00 | expedia.com | ES
e3       | u2      | search     | 2026-08-01 10:07:00 | hotels.com  | UK
e4       | u1      | booking    | 2026-08-01 10:12:00 | expedia.com | ES
```

## SQL 1 — Aggregation

Find the **number of events per event type during August 2026**, ordered from most frequent to least frequent.

---

## SQL 2 — GROUP BY + HAVING

Find all users who generated **more than 100 search events during August 2026**.

Return:

```text
user_id
search_count
```

---

## SQL 3 — Window Functions

For **each user**, return their **most recent event**.

Return the complete event record.

There can be multiple events per user.

Try to solve this using a window function rather than a self-join.

---

## SQL 4 — Deduplication

Because of an ingestion problem, the same `event_id` can appear multiple times.

Keep **only the latest copy of each event**, according to `event_timestamp`.

Return the complete record.

---

# 2. SQL — Advanced

Use the same `events` table.

## SQL 5 — LAG

For every event, calculate the timestamp of the **previous event generated by the same user**.

Return:

```text
event_id
user_id
event_timestamp
previous_event_timestamp
```

---

## SQL 6 — Time Between Events

Extend the previous query and calculate the **time elapsed between the current event and the user's previous event**.

Think about how timestamp differences work in the SQL dialect you're using.

---

## SQL 7 — Event Sequence

Find users who performed:

```text
search → click → booking
```

in that order.

Think about:

* `LAG` / `LEAD`
* ordering events per user
* whether events need to be consecutive

---

## SQL 8 — Top N Per Group

For every country, return the **3 most frequently occurring event types**.

Expected output:

```text
country
event_type
event_count
rank
```

---

## SQL 9 — Daily Active Users

Calculate the number of **unique active users per day**.

Return:

```text
date
active_users
```

---

## SQL 10 — Running Total

Calculate the cumulative number of events received during August.

Return:

```text
date
daily_events
cumulative_events
```
